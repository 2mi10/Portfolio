# VTuber表情制御モジュール (Unity 6 / C#)

Unityの基礎知識をベースに、独学で設計・実装したアバターのリアルタイム表情制御モジュールです。
uGUIのボタン操作に応じ、SkinnedMeshRendererのBlendShapeを滑らかに変更します。

# 開発の背景・独学での課題意識
講義で学び始めたUnityの基礎を超えて、より実践的な「VTuberアバターの表情制御」を自分の手で実現したいと考え、個人開発に着手しました。
開発を進める中で、以下の技術的課題に直面し、解決に取り組みました。

1. **モデル差し替えへの脆弱性**: インデックス（数値）の直書きでは、異なるアバターモデルをロードした際にコードの再書き換えが発生してしまう。
2. **表情遷移の唐突さ**: 値が一瞬で切り替わるとアバターの印象が硬くなるため、滑らかな補間処理（イージング）が必要。

## 🚀 実装の工夫と学び（課題解決のプロセス）

### 1. Mesh.GetBlendShapeIndex を用いた動的検索（モデル非依存）
- **課題**: モデルによって `Fcl_ALL_Fun` や `Fcl_ALL_Angry` など、BlendShapeの命名規則が異なりエラーの原因となっていた。
- **解決**: `Mesh.GetBlendShapeIndex()` を活用し、文字列から動的にインデックスを取得する設計を自力で調査・導入。
- **学び**: 存在しない名前が渡された場合も `-1` を返却させてガード節で処理をスキップさせることで、実行時エラー（NullReferenceやOutOfRange）を防ぐ防御的プログラミングの重要性を体得しました。

### 2. Coroutine と Lerp を用いた滑らかな表情補間
- **課題**: 単純な数値の代入では、表情が1フレームで切り替わってしまう。
- **解決**: `Time.deltaTime` と `Mathf.Lerp` を組み合わせた Coroutine 処理を構築。0.25秒かけて目標値へ滑らかに遷移させるロジックを実装。
- **学び**: ボタンの連打によってコルーチンが重複・競合するバグに遭遇し、実行前に既存の `StopCoroutine` を呼ぶ排他制御構造を構築しました。
