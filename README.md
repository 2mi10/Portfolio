# 3Dアバターの表情管理 (Unity 6.4 / C#)

Unityの基礎知識をベースに、独学で設計・実装した3Dアバターのリアルタイム表情管理システムです。
uGUIのボタン操作に応じ、アバターの表情差分（BlendShape）を滑らかに変更します。

# 開発の背景・独学での課題意識
学校の講義で学び始めたUnityの基礎を超えて、より深くの技術を学びたいと考え、個人開発に着手しました。
開発を進める中で、以下の技術的課題に直面し、解決に取り組みました。

1. **モデル差し替えへの脆弱性**: インデックスの直書きでは、異なるアバターをロードした際にコードの書き換えが発生してしまう
2. **表情遷移の硬さ**: 値が一瞬で切り替わるとアバターの印象が硬くなるため、滑らかな処理が必要。

## 実装の工夫と学び

### 1. Mesh.GetBlendShapeIndex を用いた動的検索
- **課題**: モデルによって 「Fcl_ALL_Fun」 や 「Fcl_ALL_Angry」 など、BlendShapeの命名が異なりエラーの原因となっていた。
- **解決**: 「Mesh.GetBlendShapeIndex()」 を活用し、文字列から動的にインデックスを取得する設計を導入。
- **学び**: 存在しない名前が渡された場合も 「-1」 を返させて処理をスキップさせることで、エラーを防ぐプログラムの重要性を体得しました。

### 2. Coroutine と Lerp を用いた滑らかな表情補間
- **課題**: 単純な数値の代入では、表情が１フレームで切り替わってしまう。
- **解決**: 「Time.deltaTime」 と 「Mathf.Lerp」 を組み合わせた Coroutine処理を構築。0.25秒かけて滑らかに遷移させる。
- **学び**: ボタンの連打によってコルーチンが重複・競合するバグに遭遇し、実行前に既存の 「StopCoroutine」 を呼ぶ構造を構築しました。

## 今後の展望

### モバイル（iOS / Android）環境へのマルチプラットフォーム対応と軽量化
- **目的**: スマートフォン向け配信プラットフォームでの運用を見据え、モバイル端末上での低負荷・滑らかな動作を実現する。

  - **メモリ最適化**: `Coroutine` から `UniTask` / `ValueTask` へ移行し、モバイル環境でのスパイク処理落ちを防止。
  - **タッチ操作へのUI最適化**: モバイル画面の解像度・アスペクト比に応じたレスポンシブな uGUI 設計とタップ/フリック操作への対応。
  - **プラットフォーム非依存設計**: インターフェース（`IInputProvider` 等）を導入し、PC（Windows API）とモバイル（Touch/Gyro）の入力ロジックを疎結合に分離。
